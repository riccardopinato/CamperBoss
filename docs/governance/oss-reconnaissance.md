# OSS Reuse & Reconnaissance — CamperBoss

This document applies the Master Prompt v20 reuse rule without fabricating
retroactive research.

## When reconnaissance is required

Run a 3–5 candidate reconnaissance only when the required capability is not
already covered by:

1. a relevant internal Golden;
2. the existing CamperBoss implementation;
3. an appropriate internal CERTIFIED donor.

For each external candidate record repository, revision, license, maintenance
signal, minimal reusable surface, security/privacy implications and whether the
result is COPY, ADAPT or IDEA ONLY.

## Current Step 16H

No new product feature in Step 16H requires copied OSS application code.

- CodeRabbit is integrated as a review service/configuration.
- Fastlane is integrated as a delivery tool via Gemfile/Fastfile.
- Backup hardening extends the existing CamperBoss Step 9 implementation.

Therefore a synthetic 3–5 repository search would not improve provenance and
is intentionally not performed.

## Mandatory reconnaissance before Step 17

The Local AI Micro Engine must compare at least 3–5 viable runtimes/models,
including the current Cactus/Needle candidate only as one option. Evidence must
cover license, binary/model size, RAM peak, first-token latency, tokens/s,
Android/iOS support, offline privacy, maintenance and quality on actual
CamperBoss document/manual tasks. No model is selected by parameter count alone.
